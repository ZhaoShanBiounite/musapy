# Phase 6：Indexing 套件实现计划

## 目标

实现 6 个索引算子：`transpose`, `permute`, `flip`（view，零拷贝）+ `slice/__getitem__`（view）+ `gather`, `scatter`（copy，GPU kernel）。

## 前置修复（Prerequisites）

### Fix 1: `Layout.strides` 类型变更 `Vec<usize>` → `Vec<isize>`

**原因**：flip 需要负 stride（如 `stride = -3` 表示反向遍历）。

**影响范围**（~23 处非测试代码）：
- `rust/musapy-core/src/layout.rs`：结构体定义 + `from_shape` + `from_shape_and_strides` + `compute_contiguous_strides` + `broadcast_to` + `linear_offset`
- `rust/musapy-ops/src/op_builder.rs`：已有 `s as isize` 转换 → 变为直接 clone（简化）
- `rust/musapy-ops/src/broadcast.rs`：`broadcast_strides()` 已返回 `Vec<isize>`，内部 `stride as isize` → 直接 copy
- `rust/musapy-core/src/array.rs`：`is_contiguous()` 比较逻辑
- 各处 `strides.iter().map(|&s| s as isize)` → 简化为 `.clone()` 或直接传引用

**策略**：全局替换，编译通过后跑全量测试确认无回归。

### Fix 2: `sync_and_copy_to_host` 支持 offset + 非连续布局

**当前问题**：直接从 `buffer().ptr()` 拷贝 `nbytes` 字节，忽略 `layout.offset` 和非连续 strides。

**修复方案**：
```rust
fn sync_and_copy_to_host(&self, py: Python<'_>) -> PyResult<Vec<u8>> {
    // 1. stream 同步
    // 2. 如果 is_contiguous()：
    //      base_ptr = buffer.ptr() + offset * element_size
    //      直接 memcpy nbytes
    // 3. 如果非连续：
    //      CPU: 逐元素按 stride  gather 到连续 bytes
    //      GPU: 先调 contiguous() kernel 生成临时连续 buffer，再 D2H
    //         （或简化：D2H 整个 buffer 到 host，再 CPU gather）
}
```

**P6 阶段简化方案**：GPU 非连续时，D2H 拷贝整个 buffer 到 host，再在 host 端按 strides gather。避免引入新 kernel 依赖。

### Fix 3: `Array::contiguous()` 方法（可选，P6 后期）

返回自身的连续副本。若已连续则 clone Arc（零开销），否则分配新 buffer + 按 strides gather。P6 的 `tolist()` 修复可先用 Fix 2 的 host-gather 方案，`contiguous()` 作为 P6.8 验证 view 参与运算时的辅助。

## Step 1: Layout 类型变更 + 纯函数变换（P6.1）

### 1a. `strides: Vec<usize>` → `Vec<isize>`

```rust
pub struct Layout {
    pub shape: Shape,
    pub strides: Vec<isize>,  // 改
    pub offset: usize,        // 保持 usize（offset 始终非负）
}
```

`compute_contiguous_strides` 返回 `Vec<isize>`（值仍为正）。
`from_shape_and_strides` 参数改为 `Vec<isize>`。
`linear_offset` 内部：`off as isize + indices[i] as isize * self.strides[i]`，最终 `as usize`。
`is_contiguous` 比较逻辑适配。

### 1b. 新增 Layout 变换方法

```rust
impl Layout {
    /// 转置：交换 axes 对应的 shape 和 strides。
    /// axes=None 时完全反转（等价 np.transpose(a)）。
    pub fn transposed(&self, axes: Option<&[usize]>) -> Result<Layout> { ... }

    /// 翻转指定轴：stride 取负，offset 调整到该轴末尾。
    /// offset += (shape[axis] - 1) * strides[axis]（原 stride 为正时）
    /// strides[axis] = -strides[axis]
    pub fn flipped(&self, axis: usize) -> Result<Layout> { ... }

    /// 切片：给定各维度的 (start, stop, step)。
    /// 新 shape[i] = ceil((stop - start) / step)
    /// 新 strides[i] = old_strides[i] * step
    /// 新 offset = old_offset + start * old_strides[i]（各维累加）
    pub fn sliced(&self, ranges: &[(usize, usize, usize)]) -> Result<Layout> { ... }
}
```

### 1c. 适配下游代码

- `op_builder.rs`：`a_work.layout().strides.iter().map(|&s| s as isize).collect()` → `a_work.layout().strides.clone()`
- `broadcast.rs`：`stride as isize` → 直接 `stride`（已是 isize）
- `creation.rs`：`Layout::from_shape` 无需改（内部自动用 isize）
- 所有测试中的 `vec![3, 1]` → `vec![3isize, 1]`

## Step 3: flip（P6.3）

```rust
/// flip(a, axis) — 零拷贝视图，stride 取负
pub fn flip(a: &Array, axis: usize) -> Result<Array> {
    let new_layout = a.layout().flipped(axis)?;
    Ok(Array::new_view(a, new_layout))
}
```

`Layout::flipped` 逻辑：
```rust
pub fn flipped(&self, axis: usize) -> Result<Layout> {
    if axis >= self.ndim() { return Err(...); }
    let mut new_strides = self.strides.clone();
    let mut new_offset = self.offset;
    // 调整 offset 到该轴最后一个元素
    new_offset = (new_offset as isize + (self.shape[axis] as isize - 1) * self.strides[axis]) as usize;
    new_strides[axis] = -self.strides[axis];
    Ok(Layout { shape: self.shape.clone(), strides: new_strides, offset: new_offset })
}
```

## Step 4: slice / `__getitem__`（P6.4）

### Rust 层：`indexing.rs`

```rust
/// 切片参数（单维度）
pub struct SliceSpec {
    pub start: usize,
    pub stop: usize,
    pub step: usize,  // step >= 1（负 step 暂不支持，v0.3）
}

/// slice(a, specs) — 零拷贝视图
pub fn slice(a: &Array, specs: &[SliceSpec]) -> Result<Array> {
    let ranges: Vec<(usize, usize, usize)> = specs.iter()
        .map(|s| (s.start, s.stop, s.step)).collect();
    let new_layout = a.layout().sliced(&ranges)?;
    Ok(Array::new_view(a, new_layout))
}
```

### PyO3 层：`array.rs` 的 `__getitem__`

接受 `&Bound<'_, PyAny>` 参数，解析：
- 单个 int → 降维（shape 去掉该维）
- 单个 slice → 保留维度
- tuple of int/slice → 多维
- 负索引：`-1` → `shape[i] - 1`
- slice 的 start/stop/step 解析 + clamp

返回 `PyArray`（视图）。

## 注意事项

- **零拷贝 view**：transpose/permute/flip/slice 不分配新 buffer，仅修改 Layout + Arc clone BufferRef
- **负 stride 安全**：kernel 的 `offset_nd` 已用 isize 计算，负 stride 自然支持
- **offset 始终 usize**：offset 表示从 buffer 起始到逻辑首元素的距离，始终非负（flip 通过调整 offset 到"新首元素"位置 + 负 stride 实现）
- **gather/scatter 是 copy 操作**：分配新 buffer，不共享
- **高级索引（boolean mask / fancy）推迟到 v0.3+**
- **负 step slice 推迟到 v0.3**（当前仅支持 step ≥ 1）

  pymethods 内薄委托；不启用新 feature。

## 4. 实现阶段

### Phase 0：环境与基线

**任务**：

- 基线三件套确认 v0.3 全绿：`MUSAPY_MOCK_MUSA=1 cargo test`（预期 301+ passed）、

- `./tools/check_musax_symbols.sh` 复跑确认 96/96

**交付物**：基线报告（测试数 + 版本号），任何一项不绿则先修复再进 Phase 1。

### Phase 1：互操作基础设施（DLPack 核心）

**任务**：
- vendor 最小 DLPack C 结构（`DLManagedTensor` 含 deleter 回调）+ `kDLMUSA = 100`（`dlpack.rs`，`repr(C)`）
- dtype 双向映射（004-D2）：int/uint→kDLInt/kDLUInt、f16/f32/f64→kDLFloat、bf16→kDLBfloat、
  c64/c128→kDLComplex（bits=分量位宽×2）、**bool→kDLUInt/8**（导入侧按 PyTorch 惯例映射 Uint8，
  round-trip 有损，测试显式断言此行为）；`lanes≠1` 一律拒绝。映射基准：
  `Dtype::category()`（dtype.rs:62）+ `precision_width()`（dtype.rs:75）+ `element_size()`（dtype.rs:88）
- `InteropError` 补 `DlpackImport` 变体（error.rs:68，与既有 `DlpackExport`:71 对称）；
  Python 侧 `InteropError` 异常类已存在（musapy-python/error.rs:43/:96），无需新增类
- 生命周期设计（004-D3）：导出 capsule 的 `manager_ctx` 持 `Arc<Buffer>`（经 `BufferRef::arc()`，
  buffer.rs:454-469），deleter `from_raw` 回收；`__dlpack__(stream)` 默认不强制 sync

**交付物**：dlpack.rs 编译通过 + 单元测试（结构布局/对齐、dtype 映射矩阵、deleter 调用）。

### Phase 2：DLPack 导出/导入 + round-trip（主线交付 1）

**任务**：
- `Array.__dlpack__(stream=None)` / `__dlpack_device__()`：签名加入现有 `#[pymethods]` 块
  （array.rs:33），实现委托 `interop.rs`。`__dlpack_device__` 返回 `(type_code, device_id)` 元组：
  Cpu→`(1, 0)`、Musa(id)→`(100, id)`（基准 `Device::is_musa()`/`musa_id()`，device.rs:61-71）
- 非连续视图：DLPack `DLTensor.strides` 字段导出（Layout strides），消费方按 strides 解释；
  导入侧同理按 strides 构造 Layout（musapy Array 原生支持非连续）
- `ms.from_dlpack(obj)`：模块级 `#[pyfunction]`（musapy-python/lib.rs:291 模式注册）；
  接受任何实现 `__dlpack__` 的对象：
  - `kDLMUSA(100)` 设备：零拷贝接管（新 `BufferRef` 指向同一内存，接管后调用原 deleter 转移所有权）
  - `kDLCPU(1)` 设备：构造 host Array（拷贝 + 调原 deleter）
  - 其他设备类型（含 kDLCUDA）：抛 `InteropError`（v1 范围仅 musapy 内部，L3-20）
  - capsule 格式错/未知 dtype：`InteropError::DlpackImport`，不 panic、不静默降级（004-D5）
- **torch_musa 跨库探针**（新增）：`tests/python/test_interop_torch_probe.py`，
  musapy→torch（`torch.from_dlpack`）→musapy round-trip；xfail/skip 标记，**不作为发布门禁**；
  探针结论记入 sdk-limitations 或探针报告，为 v1 跨库验证决策提供输入
- musapy→musapy round-trip 验证（L3-20）；`np.array(ms_arr)` 的 `__array__` 提前可用（Phase 3 交付）

**交付物**：`ms.from_dlpack(arr.__dlpack__())` round-trip 通过 + `test_interop.py`
（值/形状/dtype 一致、capsule 存活期、mem_stats 持平无泄漏、bool 有损行为、错误路径）+ 探针报告。

### Phase 3：NumPy 协议（主线交付 2）

**任务**：
- `__array__(dtype=None, copy=None)`：`stream.synchronize()`（stream.rs:311 模式）+
  复用 `sync_and_copy_to_host`（array.rs:524-645，已处理连续/非连续两种路径）→
  Rust 侧经 Python 调 `numpy`（运行时懒加载）构造 ndarray；**不发 warning**（L3-19）
- `.cpu()` / `.numpy()` 便捷方法：同上路径，`.cpu()` 返回 CPU Array，`.numpy()` 返回 ndarray
- `__array_ufunc__`：strict policy（004-D4）；同 device 委托既有 `musapy_ops`
  （add/subtract/multiply/divide/power/negative/absolute 及比较族）；支持 `out=`；
  跨设备抛 **`DeviceMismatch`**——固定消息格式（L3-17）：列出两侧设备
  （"musapy Array on musa:0" / "numpy.ndarray on cpu"）+ 两条修复路径
  （`ms.array(b, device=a.device)` 或 `a.cpu().numpy()`）；
  未覆盖的 ufunc 返回 `NotImplemented`。与既有 dunder（`__eq__` 等，array.rs:175-208）
  的优先级冲突需全量回归把关
- `__array_function__`：**6 函数全部原生实现**（2026-08-27 决策）：
  | 函数 | 实现 |
  |---|---|
  | `zeros_like` / `ones_like` | 直接委托现有创建算子（ops.rs 已有） |
  | `split` | 零拷贝 view（slice 组合，无新 kernel） |
  | `concatenate` | **新增 copy kernel**（kernels/elementwise.mu 或新文件）+ `ms.concatenate` 公开 API |
  | `stack` | unsqueeze（view）+ concatenate |
  | `where` | **新增三元 elementwise kernel** + broadcast + 类型提升 + `ms.where` 公开 API |
  | 其余函数 | fallback NumPy（经 `__array__` 同步，文档标注） |
- **错误模型**：`DeviceMismatch` 新异常类（musapy-python/error.rs `create_exception!` 块追加，
  继承 `MusapyError`）+ core 侧错误归属（现由 `DeviceError::Mismatch` 承担，error.rs:9，
  评估是否独立变体或复用映射）
- 导出面同步：`__init__.py`（from_dlpack/DeviceMismatch/concatenate/stack/split/where/
  memory_detail/stream_summary）+ `_core.pyi`（Array 区 :100-149 加互操作签名、
  Exceptions 区 :22-32 加 DeviceMismatch、Functions 区 :229 加模块级函数）

**交付物**：`np.array(ms_arr)` 值正确；`np.add(ms_gpu, np_cpu)` 抛 `DeviceMismatch` 且消息含修复路径；
6 函数对照 NumPy 数值全绿；既有 587+ 用例无回归。

### Phase 5：v0.3 欠账 B —— coo_matrix + 高级索引 GPU kernel

**任务**：
- **FFI 补缺**：`musparseCreateCoo` 声明 + mock stub（符号已审计：
  check_musax_symbols.sh:118；sdk-limitations :86 ✅）；先探针 `musparseCooToCsr` 符号，

- **高级索引 GPU kernel 接入**：根因是 mcc 不支持指针数组 kernel 参数
  （`const int64_t* const*` 启动 error 999，sdk-limitations 1.13）。绕行方案探针：
  **flatten 索引数组 + 偏移参数**（k 个索引指针打进单一拼接 buffer + meta 偏移字段，
  替换 `kernels.rs:338-345` extern 声明中的指针数组签名）→ 接入已实现的
  `musapy_adv_gather_*_v2`（indexing.mu:547-587）/ `musapy_nonzero_bool_v2`（indexing.mu:589-605），
  替换 `gpu_adv_index`（indexing.rs:1931）/ `mask_true_coords`（indexing.rs:2074）的 host fallback；
  目标：1M mask 从 ~500ms 降到 kernel 级。**探针失败则保持 host fallback 并在文档标注**（风险 2）
- 混合 basic+fancy 索引 `a[1:, [0,2]]`：当前在 `parse_index_item`（array.rs:336-368，

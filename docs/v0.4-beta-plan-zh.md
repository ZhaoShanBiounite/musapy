## 1. v0.4-beta 范围

### 1.1 在范围内

| 组件 | 实现方式 | 依据 |
|---|---|---|
| **DLPack 互操作**：`__dlpack__` / `__dlpack_device__` / `ms.from_dlpack` | vendor 最小 DLPack C 结构 + capsule deleter 生命周期 | L3-16 / L3-20 |
| **NumPy 协议**：`__array__` / `__array_ufunc__` / `__array_function__` | PyO3 `#[pyproto]` + strict policy | L3-17 / L3-18 / L3-19 |
| 便捷方法 `.cpu()` / `.numpy()` | D2H 拷贝 + np.ndarray 包装 | 互操作配套 |
| **错误模型扩展**：`InteropError` 落地、新增 `DeviceMismatch` | ops 层 + Python 异常映射 | L3-17 / L4-5 |
| **可观测性完整**：debug 模式补全 + `memory_detail` / `stream_summary` | core debug.rs + buffer_pool.rs | L3-26 / L3-28 |
| v0.3 欠账 A：**fftn / ifftn / rfftn / irfft / fftfreq** | muFFT 多轴 plan + fft.py 扩展 | v0.3 release note 排期 |
| v0.3 欠账 B：**coo_matrix / coo→csr** + **高级索引 GPU kernel** + **混合 basic+fancy** | muSPARSE + indexing.mu kernel 接入 + `__getitem__` | v0.3 release note 排期 / 002-D4 |
| 算子扩展：**eigh**（syevd S/D）、**batch matmul**（strided-batched）、**N-D 广播 dot** | musolver syevd + mublas SgemmStridedBatched | v0.3 plan §1.2 / 003-D6 |
| **dtype 补全**（可裁剪）：f16/bf16 全链路、cast complex→real、complex 算子扩展、标量比较 | ops/kernels 扩展 | dtype 缺口盘点 |

### 1.2 范围外（推迟）

| 组件 | 推迟到 |
|---|---|
| DLPack 跨库验证（torch_musa） | 保持推迟（L3-20：v1 仅 musapy 内部 round-trip） |
| sort / argsort | v0.4+（muThrust parallel_for 问题未确认修复，不引入） |
| PyTorch 互操作（`__torch_function__` / autograd） | v2+ / v3+（L3-21） |
| CuPy 互操作 | v1 不做（CUDA-only 物理不兼容，L3-22） |
| MUSA Graphs capture / MCCL | v2（L4-6） |
| kernel fusion / JIT / autotuning | v3+ |
| 复数 eigh（syevd 无 C/Z 变体） | 另行评估（SDK 缺口，见 sdk-limitations 2.3） |
| 复数 max/min/argmax/argmin | 永久拒绝（复数无全序，002-D3） |

## 4. 实现阶段

### Phase 1：互操作基础设施（DLPack 核心）

**任务**：
- vendor 最小 DLPack C 结构（`DLManagedTensor` 含 deleter 回调）+ `kDLMUSA = 100`
- `InteropError` 补 `DlpackImport` 变体；Python 侧 `InteropError` 异常类映射补全
- `Array` 互操作方法骨架：`__dlpack__` 的 Rust 侧 `DLManagedTensor` 构造、
  buffer `Arc` 生命周期管理（capsule deleter 持 Arc 防提前释放）、跨 device 时 D2H

**交付物**：dlpack.rs 编译通过 + 单元测试（结构布局、deleter 调用）

### Phase 2：DLPack 导出/导入 + round-trip（主线交付 1）

**任务**：
- `Array.__dlpack__(stream=None)` / `__dlpack_device__()`（PyO3 方法 + pyi）
- `ms.from_dlpack(obj)`：接受任何实现 `__dlpack__` 的对象；musa 设备 buffer 零拷贝接管，
  cpu 设备 D2H；deleter 释放时归还所有权
- musapy→musapy round-trip 验证（L3-20）；`np.array(ms_arr)` 的 `__array__` 提前可用
- 跨库验证（torch_musa）推迟

**交付物**：`ms.from_dlpack(arr.__dlpack__())` round-trip 通过 + 测试

### Phase 3：NumPy 协议（主线交付 2）

**任务**：
- `__array__(dtype=None, copy=None)`：`np.array(ms_arr)` → stream.synchronize + D2H
  （L3-19，不发 warning）
- `__array_ufunc__`：strict policy，同 device 内委托既有 ops；跨设备抛 `DeviceMismatch`
  + 修复消息（L3-17）
- `__array_function__`：v1 范围 `concatenate/stack/split/zeros_like/ones_like/where`；
  其余 fallback NumPy（触发 `.cpu()` 同步）
- `.cpu()` / `.numpy()` 便捷方法

**交付物**：`np.add(ms_arr, np_ndarray)` 跨设备报错消息准确 + `np.array(ms_arr)` 值正确

### Phase 4：v0.3 欠账 A —— fftn/多轴/irfft

**任务**：
- `fftn/ifftn/rfftn`（任意 axes，muFFT 逐轴 plan）+ `irfft`（复数→实数，缩放语义对齐 NumPy）
- `fftfreq/rfftfreq` 辅助函数
- fft 多 shape plan 缓存（可选优化）

### Phase 5：v0.3 欠账 B —— coo_matrix + 高级索引 GPU kernel

**任务**：
- `ms.sparse.coo_matrix` + coo→csr 归并（muSPARSE CreateCoo 或 host 归并）
- 高级索引 GPU kernel 接入：`musapy_adv_gather_*_v2`/`musapy_nonzero_bool_v2`（kernels
  已声明）替换 host fallback——探针验证 mcc 参数方案（指针数组 error 999 的绕行方案：
  flatten 索引数组 + 偏移参数）；1M mask 从 ~500ms 降到 kernel 级
- 混合 basic+fancy 索引 `a[1:, [0,2]]`（当前抛 PyTypeError，v0.4 实现 NumPy 语义）

### Phase 6：可观测性完整（L4-5 补全）

**任务**：
- Debug 模式补全（L3-26）：sync DAG 环检测、buffer alias 检测 dump、Arc count assert、
  释放后 buffer 填 `0xDEADBEEF`、op 参数完整 dump
- `ms.memory_detail(device)`（遍历 BufferPool，标注开销）/ `ms.stream_summary()`（L3-28）
- 错误模型统一：`DeviceMismatch` / `InteropError` 全链路覆盖 + 文档

### Phase 7：算子扩展

**任务**：
- **eigh**：musolver `syevd` S/D（musa_x_ffi.rs 声明 + linalg 实现）；仅实数
- **batch matmul**：`mublasSgemmStridedBatched` FFI 声明 + 3D+ 广播语义实现（替代逐 batch 物化）
- **N-D 广播 dot**（003-D6）：NumPy sum-product 语义

### Phase 8：dtype 补全（可裁剪项）

**任务**：
- f16/bf16 创建/读取/cast/运算全链路（当前 4 处 NotImplementedError）
- cast complex→real 补 kernel（op_builder 显式拒绝路径）
- complex 算子扩展（pow、unary exp/log/sin/cos/sign）
- 标量比较 `a > 2.0`（mask 便捷路径）

### Phase 9：验证与发布

**任务**：
- 版本统一 0.4.0-beta（Cargo workspace / pyproject / pyi 头注释）
- 全量回归（pytest + cargo test 双模式）+ §1.3 端到端验收
- release note + CHANGELOG + ADR 更新（v0.4-beta 决策转 Accepted）+ tag `v0.4.0-beta`

## 14. 验收标准

- DLPack round-trip：musapy 导出 → 导入，值/形状/dtype 一致，无 buffer 泄漏（mem_stats 持平）
- NumPy 协议：`np.array(ms_arr)` 值正确；跨设备 ufunc 抛 `DeviceMismatch` + 修复消息
- fftn/irfft/coo_matrix/混合索引/eigh/batch matmul 对照 NumPy 数值全绿
- 高级索引 GPU kernel 接入后 1M mask 延迟显著低于 host fallback 基线（~500ms）
- debug 模式补全项有测试覆盖；`memory_detail`/`stream_summary` 输出正确
- 全量 pytest + cargo test 通过（真机 + mock 双模式）

## 15. 范围外（推迟）

见 §1.2 表。核心排除：sort/argsort（muThrust 依赖）、跨库 DLPack 验证、PyTorch/CuPy 互操作、
MUSA Graphs / MCCL（v2）、kernel fusion / JIT（v3+）、复数 eigh（SDK 缺口）。

## 16. 风险登记表

| # | 风险 | 影响 | 预案 |
|---|---|---|---|
| 1 | DLPack 无独立头文件 | 结构定义需 vendor | 最小结构（~150 行），kDLMUSA=100；不依赖 torch |
| 2 | 高级索引 GPU kernel 曾受 mcc error 999 阻塞 | kernel 接入失败 | 探针验证 flatten 索引数组方案；失败则保持 host fallback（标注） |
| 3 | eigh 复数缺 syevd C/Z | 复数特征值不可做 | eigh 仅实数；复数另行评估 |
| 4 | f16/bf16 全链路工作量大 | Phase 8 延期 | 列为可裁剪项，来不及随 v0.4.x 补 |
| 5 | batch matmul strided-batched ABI 差异 | 3D+ 语义实现复杂 | 先 probe 验证 `mublasSgemmStridedBatched` 符号与语义；失败走逐 batch（保留物化路径） |
| 6 | NumPy 协议与既有 dunder（`__eq__` 等）冲突 | 行为回归 | `__array_ufunc__` 返回 NotImplemented 时走既有路径；全量回归把关 |

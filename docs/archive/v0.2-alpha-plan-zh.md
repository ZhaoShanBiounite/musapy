### 1.3 成功定义

以下 Python 代码在 MUSA 硬件上端到端跑通：

```python
import musapy as ms

ms.set_default_device("musa:0")

# broadcast + 类型提升（002-D1, 002-D2）
a = ms.array([[1.0], [2.0], [3.0]])          # shape (3,1), float32
b = ms.array([10, 20, 30, 40])               # shape (4,), int64
c = a + b                                     # broadcast → (3,4)，提升到 float32
print(c.shape)                                # (3, 4)

# elementwise 套件
d = ms.sin(c) * ms.exp(ms.array(0.1))         # 一元 + 二元
e = ms.pow(d, 2.0)
f = ms.clamp(e, 0.0, 1.0)

# comparison（输出 bool）
mask = c > 15.0                               # shape (3,4), bool

# reduction（002-D3）
s = ms.sum(c)                                 # 0-dim，全 reduce
row = ms.sum(c, axis=1)                       # shape (3,)
col_k = ms.sum(c, axis=0, keepdims=True)      # shape (1,4)
m = ms.mean(c)
am = ms.argmax(c, axis=1)                     # shape (3,), int64

# init（002-D5）
z = ms.zeros((2, 3))                          # float32（L0-7 level-5）
o = ms.ones_like(z)                           # 继承 z 的 dtype/device
r = ms.arange(5)                              # int64（NumPy 推断）
lin = ms.linspace(0.0, 1.0, 5)                # float64
eye = ms.eye(3)                               # float32

# indexing（002-D4）
t = ms.transpose(c)                           # view, shape (4,3)，共享 buffer
sl = c[0:2, ::2]                              # view, shape (2,2)
fl = ms.flip(c, axis=1)                       # view
g = ms.gather(c, ms.array([0, 2]), axis=1)    # copy, shape (3,2)

# 同步 + 回读
ms.Stream("musa:0").synchronize()
print(row.tolist())
```

## 2. 前置条件

v0.1-alpha 已验证 MUSA SDK 健康与 stream-ordered alloc/free（见 v0.1 计划第 2 节）。v0.2 **不需要**新的硬件前置验证，但实现者需注意：

- **新 `.mu` 文件需注册到 build.rs**：v0.1 的 `rust/musapy-ops/build.rs` 只硬编码编译 `elementwise.mu`。v0.2 新增 `reduction.mu` / `init.mu` / `indexing.mu` 必须逐个加入编译与归档（Phase 4/5/6 各含此任务）。
- **kernel ABI 版本**：elementwise/comparison 走 `_v2` stride-aware 符号；按 L4-3，`_v1` 在 v0.2 内保留。
- **无 GPU 开发**：沿用 `MUSAPY_MOCK_MUSA` mock 模式，所有新 kernel 需在 `kernels.rs` 配 mock stub，保证 `cargo test` 与 CPU pytest 在无硬件环境可跑。

## 4. 实现阶段

v0.2-alpha 分 7 个阶段。Phase 1 是基石（后续 elementwise/comparison 全部依赖它）。
Phase 2-3 依赖 Phase 1。Phase 4/5/6 相互独立，可并行。Phase 7 集成验证。

| 阶段 | 工作量 | 依赖 | 可并行？ |
|---|---|---|---|
| 1. stride-aware ABI + broadcast | 1.5-2 周 | v0.1 | — |
| 2. elementwise + 类型提升 | 1.5-2 周 | Phase 1 | — |
| 3. comparison | 3-4 天 | Phase 1 | 可（与 Phase 2 并行） |
| 4. reduction | 1.5-2 周 | Phase 1 | 可（与 5/6 并行） |
| 5. init / creation | 1-1.5 周 | v0.1（弱依赖 Phase 1） | 可（与 4/6 并行） |
| 6. indexing | 1.5-2 周 | Phase 1（view 需 stride-aware） | 可（与 4/5 并行） |
| 7. 验证与文档 | 3-4 天 | Phase 2-6 | — |

**合计**：7-9 周（Phase 4/5/6 并行可压缩到 6-7 周）。

## Phase 1：stride-aware kernel ABI + broadcast 基础

**目标**：elementwise kernel 支持 N 维 stride；broadcast 可用；`add` 迁移到新 ABI。这是 v0.2 的基石（002-D2）。

### 任务

| 任务 ID | 任务 | 交付物 | 依据 |
|---|---|---|---|
| P1.1 | `common.h` 新增 N 维索引辅助 | `offset_nd(linear_idx, shape, strides, ndim)`、`grid_size_1d` 保留 | 002-D2 |
| P1.2 | elementwise kernel ABI 升级到 `_v2`（stride-aware） | `elementwise.mu`：`musapy_add_f32_v2(a,b,c,ndim,shape,a_strides,b_strides,stream)` | 002-D2、L4-3 |
| P1.3 | 广播形状计算（NumPy 规则） | `broadcast.rs::broadcast_shape(&[&[usize]]) -> Result<Shape>` | 002-D2 |
| P1.4 | 广播 stride 推导（含与输入自身 stride 组合） | `broadcast.rs::broadcast_strides(layout, target_shape) -> Vec<isize>` | 002-D2 |
| P1.5 | `Layout` 扩展 `broadcast_to(shape)` | `musapy-core/layout.rs` 纯函数 | 002-D2 |
| P1.6 | `op_builder.rs` 抽出 elementwise 公共骨架 | 3-phase（解析/launch/后处理）泛化为二元/一元 | L1-12、L2-4 |
| P1.7 | `add` 迁移到 `_v2` ABI（含 broadcast） | `elementwise.rs::add` 支持不同形状输入 | 002-D2 |
| P1.8 | `kernels.rs` 更新 extern 声明 + mock stub（`_v2`） | real + mock 双路径同签名 | L2-2 |
| P1.9 | 0-dim 标量广播支持 | `shape=[]` 操作数 stride 全 0 | L1-11 |
| P1.10 | broadcast 单元 + Python 测试 | `test_elementwise.py::TestBroadcast` | — |

### 接口签名

```rust
// broadcast.rs
pub fn broadcast_shape(shapes: &[&[usize]]) -> Result<Shape>;          // NumPy 规则，不兼容抛 ShapeError
pub fn broadcast_strides(layout: &Layout, target: &Shape) -> Vec<isize>; // 元素为单位，广播维为 0

// elementwise kernel ABI（C，elementwise.mu）
// void musapy_add_f32_v2(const float* a, const float* b, float* c,
//                        int ndim, const size_t* shape,
//                        const ssize_t* a_strides, const ssize_t* b_strides,
//                        musaStream_t stream);
```

### 验收

```python
import musapy as ms
ms.set_default_device("musa:0")
a = ms.array([[1.0], [2.0], [3.0]])   # (3,1)
b = ms.array([10.0, 20.0, 30.0, 40.0])# (4,)
c = ms.add(a, b)                       # (3,4)
assert c.shape == (3, 4)
print(c.tolist())                      # [[11,21,31,41],[12,22,32,42],[13,23,33,43]]
```

## 14. 风险登记表

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| stride-aware kernel ABI 改造引入性能回退（连续 1D 也走 N 维路径） | 中 | 中 | ✅ 已缓解：Phase A 连续快路径 + Phase B 并行 reduction + Phase C-lite CPU 开销优化（-39% 延迟） |
| broadcast stride 与输入自身 stride 组合错误（非 contiguous 输入） | 中 | 高 | Phase 1 专测 transpose-view 再 broadcast 用例 |
| 类型提升「预 cast」多一次 pass 的性能开销 | 中 | 低 | 文档说明；小数组可接受；fusion 留 v3 |
| reduction block-reduce kernel 在大 axis 上正确性 | 中 | 高 | 多 shape/axis 矩阵测试；对照 NumPy |
| 整型累加溢出测试遗漏 | 低 | 中 | P7.3 专项溢出用例 |
| view 共享 buffer 导致用户误用（写 view 影响原数组） | 中 | 低 | getting-started 明确说明 view 语义 |
| `__eq__` dunder 破坏 Array 可哈希性 | 低 | 中 | 显式 `__hash__=None`，文档说明用 `ms.equal` 风格 |
| 新 `.mu` 未注册 build.rs 导致链接错误 | 中 | 低 | 每 Phase 含 build.rs 任务 + clean build 验证 |
| 开发者无 MUSA 硬件 | 高 | 高 | mock 模式 + CPU fallback；同事硬件验证（Phase 7） |

### 1.3 成功定义

以下 Python 代码在 MUSA 硬件上端到端跑通：

```python
import musapy as ms

ms.set_default_device("musa:0")

# Array 创建
a = ms.array([1.0, 2.0, 3.0], dtype=ms.float32)
b = ms.array([4.0, 5.0, 6.0], dtype=ms.float32)

# 最小 op（elementwise add）
c = ms.add(a, b)   # → Array([5.0, 7.0, 9.0], device=musa:0)

# Stream context
s = ms.Stream("musa:0")
with ms.stream(s):
    d = ms.add(a, b)   # 绑定到 s

# Resolution feedback
print(a.device)
# Device(musa:0)  # resolved from: global_default (musa:0), set via ms.set_default_device() at <stdin>:3

# 同步 + 回读
s.synchronize()
print(c.tolist())   # [5.0, 7.0, 9.0]

# 内存汇总
ms.memory_summary()
# Device: musa:0
# Used by musapy: 48 bytes (2 buffers)
# Cached (pool): 0 bytes
```

## 2. 验证前置条件

**在开始 v0.1-alpha 实现前**，有 MUSA 硬件的同事必须验证：

### 2.1 stream-ordered alloc/free 测试（L3-15）

最小 C 测试程序（非 Rust、非 Python —— 纯 MUSA runtime）：

```c
// verify_stream_ordered.c
#include <musa_runtime.h>
#include <stdio.h>

int main() {
    // 检查能力
    int supported = 0;
    musaDeviceGetAttribute(&supported, musaDevAttrMemoryPoolsSupported, 0);
    if (!supported) {
        printf("FAIL: stream-ordered allocator not supported\n");
        return 1;
    }

    // 创建两个 stream
    musaStream_t s1, s2;
    musaStreamCreate(&s1);
    musaStreamCreate(&s2);

    // 在 s1 上分配
    void* ptr;
    musaMallocAsync(&ptr, 1024, s1);

    // 在 s1 上记录写 event
    musaEvent_t write_ev;
    musaEventCreate(&write_ev);
    musaEventRecord(write_ev, s1);

    // s2 等待 s1 的写完成
    musaStreamWaitEvent(s2, write_ev, 0);

    // 在 s2 上使用（实际是 kernel launch；这里用 memcpy 代替）
    // ...（省略 kernel launch，用 musaMemcpyAsync 代替）

    // 在 s2 上记录读 event
    musaEvent_t read_ev;
    musaEventCreate(&read_ev);
    musaEventRecord(read_ev, s2);

    // 在 s2 上释放（最后使用 stream，策略 b）
    // s2 必须 wait read_ev（trivially true，因为 read 在 s2 上记录）
    musaFreeAsync(ptr, s2);

    // 同步
    musaStreamSynchronize(s2);

    printf("PASS: stream-ordered alloc/free works\n");
    return 0;
}
```

**编译运行**：
```bash
mcc -o verify_stream_ordered verify_stream_ordered.c -lmusart
./verify_stream_ordered
```

**验收**：输出 `PASS`。如果 `FAIL`，v0.1-alpha 必须用 deferred-free fallback（L3-11）。

### Phase 3 Cargo 特性
musapy-core/Cargo.toml 新增 feature：

[features]default = []stream-ordered = []  # 启用 musaMallocAsync/musaFreeAsync 路径（需 5.x SDK）
构建命令：

- 3.x/4.x 环境：cargo build（默认，deferred-free）
- 5.x 环境：cargo build --features stream-ordered（stream-ordered）
代码约定：

#[cfg(feature = "stream-ordered")] gate 所有 async API 声明和调用
- Buffer::alloc/Drop 内部根据 feature 选择路径
- deferred_free.rs 只在默认路径编译，stream-ordered feature 下不编译
- runtime probe（probe_memory_pools_supported）作为双重保险——即使编译了stream-ordered feature，启动时也 probe；不支持则回退到 deferred-free


### 验收
默认路径（deferred-free，3.x/4.x/5.x）：

```let dev = Device::Musa(0);let stream = Stream::new(dev, 0)?;let buf = Buffer::alloc(1024, dev, &stream)?;buf.record_write(&stream);// ... use buffer ...drop(buf);  // → 入 deferred-free 队列，不立即 freeStream::synchronize(&stream)?;  // → 批量 reclaim，musaFree
stream-ordered 路径（--features stream-ordered，仅 5.x）：

let dev = Device::Musa(0);let stream = Stream::new(dev, 0)?;let buf = Buffer::alloc(1024, dev, &stream)?;  // → musaMallocAsyncbuf.record_write(&stream);// ... use buffer ...drop(buf);  // → musaFreeAsync，stream-ordered freeStream::synchronize(&stream)?;  // 无需 reclaim（free 已 stream-ordered）
两条路径对外行为一致：用户代码（alloc/record_write/drop/synchronize）完全相同，差异仅在内部实现。feature 切换不影响 API。
```

### kernel 代码（`kernels/elementwise.mu`）

```cpp
#include "include/common.h"

template <typename T>
__global__ void musapy_add_kernel(
    const T* __restrict__ a,
    const T* __restrict__ b,
    T* __restrict__ c,
    size_t n
) {
    size_t idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        c[idx] = a[idx] + b[idx];
    }
}

extern "C" {
    void musapy_add_f32_v1(
        const float* a, const float* b, float* c,
        size_t n, musaStream_t stream
    ) {
        musapy_add_kernel<float><<<grid_size_1d(n), 256, 0, stream>>>(a, b, c, n);
    }

    void musapy_add_f64_v1(
        const double* a, const double* b, double* c,
        size_t n, musaStream_t stream
    ) {
        musapy_add_kernel<double><<<grid_size_1d(n), 256, 0, stream>>>(a, b, c, n);
    }
}
```

## 14. 风险登记表

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| MUSA stream-ordered free 不按预期工作 | 低 | 高 | 实现前验证（2.1 节）；fallback 到 deferred-free（L3-11） |
| thread-local 默认继承有 bug | 中 | 中 | 全面 thread-scoped 测试（Phase 4 验收） |
| PyO3 GIL 管理导致死锁 | 低 | 高 | 一致用 `py.allow_threads`；多线程 Python 下测试 |
| BufferPool GC 导致卡顿 | 中 | 低 | GC 可配；默认 60 秒间隔较保守 |
| 用户升级时 ABI 版本不匹配 | 低 | 中 | 启动校验（L2-1）；清晰错误消息 |
| MUSA SDK 版本不兼容 | 中 | 高 | 文档说明支持的 SDK 版本；CI 测试矩阵 |
| 开发者无 MUSA 硬件测试 | 高 | 高 | 同事验证（第 2 节）；本地用 mock FFI |
| OpBuilder capture-safe 约束过严 | 低 | 中 | v0.1 只有 `add`；v0.2 前完善模式 |

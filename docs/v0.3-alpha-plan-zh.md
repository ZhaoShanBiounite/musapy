## 1. v0.3-alpha 范围

### 1.1 在范围内

| 组件 | 实现方式 | 依据 |
|---|---|---|
| linalg：matmul / dot / lu / qr / svd / solve | **muBLAS + muSOLVER**（C ABI，不写数学 kernel） | L4-1（`dot` 为补充项，003-D6） |
| random：rand / randn / uniform / normal / bernoulli | **muRAND** | L4-1 |
| fft：fft / fftn / ifft / rfft | **muFFT**（前置：complex64/128 落地） | L4-1 |
| sparse：csr_matrix / coo_matrix / spmv / spmm | **muSPARSE** | L4-1 |
| reduction 补全：`axis=tuple` 多轴归约、复数 sum/mean | 扩展 `reduction.mu` + kernel 实例化 | 002-D3 |
| 高级索引：boolean mask / fancy indexing | 扩展 `indexing.mu` + `__getitem__` | 002-D4 |
| 错误模型扩展：新增 `LinAlgError`（继承 `MusapyError`，奇异矩阵等）；高级索引越界抛 **Python 内置 `IndexError`**（NumPy 兼容） | ops 层 | L3-5 扩展（003-D3） |
| ~~每算子 CPU fallback（宿主库 / 纯 Rust）~~ + mock stub | ~~沿用 v0.2 模式~~；mock stub 保留 | 无 GPU 可测（mock） |

**实现来源总原则（关键）**：L4-1 已锁定数学库走 MUSA SDK 自带轮子。本机 SDK 3.1.0 已实测装齐
muBLAS / muSOLVER / muRAND / muFFT / muSPARSE（头文件 + `.so` 全部就位，见 §2），
v0.3 **不新增手写数学 kernel**，只写 Rust FFI 绑定层。新 `.mu` kernel 仅用于两处补全：
高级索引（mask / fancy）与 complex 归约。

**与 L2-3 的边界澄清（记入 ADR-003）**：L2-3 规定 musapy-core「仅依赖 MUSA runtime API、
禁止调用 MUBLAS」，但其职责表同时列有「MUBLAS handle 表」。v0.3 按如下边界执行：
`musa_x_ffi.rs`（extern 声明）与 `math_handle.rs`（handle/plan/generator 生命周期）属
**线程安全全局基础设施**，放 musapy-core；一切**计算调用**（gemm/getrf/fft/spmv 等）只在
musapy-ops 发起；5 个 MUSA-X 库的**链接**由 musapy-ops/build.rs 发出，musapy-core/build.rs
保持 musart-only（其 L2-3 注释继续有效）。

**CPU fallback 与 L4-2 的关系**：L4-2 推迟的是**独立 `musapy-cpu` crate**（v2+）。本计划的
CPU fallback 是**算子内嵌路径**（v0.2 既有惯例，elementwise/comparison/indexing 已实现），
不构成冲突。

### 1.3 成功定义

以下 Python 代码在 MUSA 硬件上端到端跑通：

```python
import musapy as ms

ms.set_default_device("musa:0")

# ---- linalg（L4-1：muBLAS + muSOLVER）----
a = ms.array([[1.0, 2.0], [3.0, 4.0]])          # (2,2) float32
b = ms.array([[5.0, 6.0], [7.0, 8.0]])
c = ms.matmul(a, b)                               # (2,2)
x = ms.solve(a, ms.array([1.0, 2.0]))             # 解 a·x = b
q, r = ms.qr(a)                                   # QR 分解（reduced）
u, s, vh = ms.svd(a)                              # SVD，s 降序
lu, piv = ms.lu(a)                                # LU 分解（(LU, pivots) 对齐 torch.linalg.lu）

# ---- random（L4-1：muRAND）----
r1 = ms.random.rand((2, 3))                       # [0,1) uniform
r2 = ms.random.randn((2, 3))                      # 标准正态
r3 = ms.random.uniform(-1.0, 1.0, (4,))           # [-1, 1)
r4 = ms.random.bernoulli(0.5, (4,))               # {0,1} bool

# ---- fft（L4-1：muFFT，complex 落地）----
f = ms.fft.fft(ms.array([1.0, 2.0, 3.0, 4.0]))    # complex64 输出
g = ms.fft.ifft(f)                                # 反变换（normalization 1/N）
rf = ms.fft.rfft(ms.array([1.0, 2.0, 3.0, 4.0]))  # 实输入 → 形状 (N//2+1,)

# ---- sparse（L4-1：muSPARSE）----
csr = ms.sparse.csr_matrix(
    (ms.array([1.0, 2.0, 3.0]), ms.array([0, 2, 3]), ms.array([0, 1, 1, 4])),
    shape=(3, 4),
)
y = csr @ ms.array([1.0, 2.0, 3.0, 4.0])          # spmv

# ---- reduction 补全（002-D3）----
s2 = ms.sum(a, axis=(0, 1))                       # tuple 多轴 → 0-dim
s3 = ms.sum(a, axis=(0,), keepdims=True)          # shape (1,2)
sc = ms.sum(ms.array([1+2j, 3+4j], dtype=ms.complex64))  # 复数 sum

# ---- 高级索引（002-D4）----
mask = a > 2.0
sel = a[mask]                                     # boolean mask → 1D copy
fancy = a[ms.array([[0, 1], [1, 0]])]             # fancy indexing → copy, (2,2)

ms.Stream("musa:0").synchronize()
print(c.tolist(), x.tolist(), s.tolist())
```

> 注：示例中 complex 相关行（`ms.array([1+2j, ...], dtype=ms.complex64)`、复数 sum、fft 的
> complex 输出读回）依赖 P5.1 的 complex 落地 —— v0.2 的 `ms.array` complex 创建与
> `tolist()`/`item()` complex 分支均抛 `NotImplementedError`（musapy-python ops.rs/array.rs
> 实测）。故 §1.3 端到端验证安排在 Phase 5 完成之后（P9.2）。

## 2. 前置条件

v0.2-alpha 已验证 MUSA SDK 健康、stream-ordered alloc/free、stride-aware kernel 与 GPU
正确性。v0.3 新增的前置验证（**Phase 1 必须完成**）：

- **MUSA-X 库本机就位（已实测）**：`/usr/local/musa/lib/` 含 `libmublas.so`、
  `libmusolver.so`、`libmurand.so`、`libmufft.so`（+ `libmtfft-device-*.so` 按 arch 变体）、
  `libmusparse.so`；`/usr/local/musa/include/` 含 `mublas.h`、`musolver.h`、`murand.h`、
  `mufft.h`、`musparse.h`。SDK 版本 **3.1.0**（mp_21/mp_22，与 MTT S4000 匹配）。
  musapy-core `build.rs` 现有注释已预留：「不链接 mublas/mudnn/mccl（那些是 v0.3+ 的事）」。
- **muSOLVER 例程覆盖（2026-08-06 头文件级核对，提前完成 P1.1 主体）**：
  `getrf / getrs / geqrf / gesvd` 均齐 S/D/C/Z；`orgqr` 仅 S/D（复数对应 `cungqr` C/Z）；
  `syevd` S/D（+Batched）存在；**`gesdd` 不存在**（不可用作 gesvd 替代）。
  关键差异：musolver **没有独立 Dn 句柄** —— 全部例程形如
  `musolverSgetrf(mublasHandle_t handle, ...)`，与 muBLAS 共享句柄、共用 `mublasStatus_t`。
  P1.1 剩余工作：运行期符号验证（.so 与头文件一致性）+ bufferSize/辅助例程清单。
- **宿主 OpenBLAS 探测**：CPU fallback 首选链接宿主 OpenBLAS（cblas / lapacke）；
  缺失时编译期降级为纯 Rust 朴素实现（仅功能正确，性能不承诺）。`apt install libopenblas-dev` 为建议安装。
- **complex dtype 现状**：musapy-core `dtype.rs` 已有 Complex64 / Complex128 且类型提升
  已支持（`is_complex()`），但：① elementwise / reduction kernel 未实例化 complex；
  ② Python 侧 `ms.array` complex 创建、`tolist()` / `item()` complex 分支均抛
  `NotImplementedError`（musapy-python ops.rs / array.rs 实测）。两处都属 Phase 5
  前置任务（P5.1）。
- **无 GPU 开发**：沿用 `MUSAPY_MOCK_MUSA` mock 模式。所有数学库 FFI 需在
  `musa_x_ffi.rs` 配 mock stub，保证 `cargo test` 与 CPU pytest 在无硬件环境可跑。
- **许可约束**：musapy 是 MIT。CPU FFT **不链接 FFTW**（GPL-2+ 传染性冲突），
  用纯 Rust 自研 radix-2（P5.6）。linalg 宿主库用 OpenBLAS（BSD-3 兼容 MIT）。

SDK 例程覆盖核对。这是 v0.3 的基石（L4-1 的实现来源全部经由此层）。

### 接口签名

```rust
// musa_x_ffi.rs（手写 extern，对标 mublas.h / musolver.h / murand.h / mufft.h / musparse.h）
pub type mublasHandle_t = *mut c_void;      // 对标 cublasHandle_t；musolver 复用此句柄
pub type murandGenerator_t = *mut c_void;   // 对标 curandGenerator_t
```

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|

| FFTW GPL-2+ 与 MIT 许可冲突 | — | 高 | 已规避：CPU fft 纯 Rust 自研 radix-2（P5.6） |

## 附录 A：加一个数学库算子的标准清单

以新增 linalg 算子 `matmul` 为例：

1. `rust/musapy-core/src/musa_x_ffi.rs`：对照 `mublas.h` 核对 `mublasSgemm` 等签名，
   加 extern 声明（real）+ mock stub（同签名）
2. `rust/musapy-core/src/math_handle.rs`：确认 handle 获取/释放路径（无则注册）
3. `rust/musapy-ops/src/linalg.rs`：`pub fn matmul(...)`（形状推导 → FFI 调用 → 后处理）
   + CPU fallback（`cblas_sgemm` 或朴素实现）
4. `rust/musapy-ops/src/lib.rs`：`pub use linalg::matmul;`
5. `rust/musapy-python/src/ops.rs`：`#[pyfunction] pub fn matmul(...)`（含 debug-frame 块）
6. `rust/musapy-python/src/lib.rs`：`m.add_function(wrap_pyfunction!(ops::matmul, m)?)?;`
7. `rust/musapy-python/src/array.rs`：`__matmul__` dunder（如适用）
8. `python/musapy/__init__.py`：加入 import 块 + `__all__`
9. `python/musapy/_core.pyi`：`def matmul(...)` 存根（+ dunder 存根）
10. `tests/python/test_linalg.py`：CPU + MUSA-gated 测试（对照 NumPy）
11. 若新增外部链接（新 MUSA-X 库或宿主库）：先扩展 `musapy-ops/build.rs` 链接/探测
    （musapy-core/build.rs 保持 musart-only，L2-3）

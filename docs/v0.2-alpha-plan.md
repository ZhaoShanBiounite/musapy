## 1. v0.2-alpha Scope

### 1.1 In Scope

| Component | Basis |
|---|---|
| Stride-aware elementwise kernel ABI (per-operand stride) | 002-D2 |
| Broadcast (NumPy rules, strides=0) | 002-D2, L4-1 |
| Type promotion for binary ops (`promote()` + GPU precision alignment) | 002-D1, L1-5, L1-14 |
| elementwise: sub / mul / div / sin / cos / exp / log / pow / abs / sign / clamp | L4-1 |
| `Array.astype()` (also serves as internal cast infrastructure) | 002-D1 |
| comparison: == / != / < / > / <= / >= (returns bool) | L4-1 |
| reduction: sum / max / min / mean / prod / argmax / argmin / cumsum (axis=None/int + keepdims) | 002-D3, L4-1 |
| init: zeros / ones / full / arange / linspace / eye / zeros_like / ones_like | 002-D5, L4-1, L3-18 |
| indexing: transpose / permute / flip / slice (view) + gather / scatter (copy) | 002-D4, L4-1 |
| CPU fallback + mock stub per op (testable without GPU) | reuse v0.1 pattern |

### 1.2 Out of Scope (Deferred)

| Component | Deferred to |
|---|---|
| reduction multi-axis `axis=tuple` | late v0.2 / v0.3 |
| complex reduction (sum/mean) | v0.3 |
| advanced indexing (boolean mask / fancy indexing) | v0.3+ |
| math library ops (linalg / random / fft / sparse) | v0.3-alpha |
| DLPack interop | v0.4-beta |
| NumPy protocols (`__array_ufunc__`, etc.) | v0.4-beta |
| MUSA Graphs capture implementation | v2 |
| MCCL distributed | v2 |

### 1.3 Success Definition

The following Python code runs end-to-end on MUSA hardware:

```python
import musapy as ms

ms.set_default_device("musa:0")

# broadcast + type promotion (002-D1, 002-D2)
a = ms.array([[1.0], [2.0], [3.0]])          # shape (3,1), float32
b = ms.array([10, 20, 30, 40])               # shape (4,), int64
c = a + b                                     # broadcast → (3,4), promoted to float32
print(c.shape)                                # (3, 4)

# elementwise suite
d = ms.sin(c) * ms.exp(ms.array(0.1))         # unary + binary
e = ms.pow(d, 2.0)
f = ms.clamp(e, 0.0, 1.0)

# comparison (returns bool)
mask = c > 15.0                               # shape (3,4), bool

# reduction (002-D3)
s = ms.sum(c)                                 # 0-dim, full reduction
row = ms.sum(c, axis=1)                       # shape (3,)
col_k = ms.sum(c, axis=0, keepdims=True)      # shape (1,4)
m = ms.mean(c)
am = ms.argmax(c, axis=1)                     # shape (3,), int64

# init (002-D5)
z = ms.zeros((2, 3))                          # float32 (L0-7 level-5)
o = ms.ones_like(z)                           # inherits z's dtype/device
r = ms.arange(5)                              # int64 (NumPy inference)
lin = ms.linspace(0.0, 1.0, 5)                # float64
eye = ms.eye(3)                               # float32

# indexing (002-D4)
t = ms.transpose(c)                           # view, shape (4,3), shares buffer
sl = c[0:2, ::2]                              # view, shape (2,2)
fl = ms.flip(c, axis=1)                       # view
g = ms.gather(c, ms.array([0, 2]), axis=1)    # copy, shape (3,2)

# synchronize + read back
ms.Stream("musa:0").synchronize()
print(row.tolist())
```

## 2. Prerequisites

v0.1-alpha already validated MUSA SDK health and stream-ordered alloc/free (see v0.1 plan section 2). v0.2 requires **no** new hardware pre-validation, but implementers should note:

- **New `.mu` files must be registered in build.rs**: v0.1's `rust/musapy-ops/build.rs` hardcodes compilation of `elementwise.mu` only. v0.2's new `reduction.mu` / `init.mu` / `indexing.mu` must each be added to compilation and archiving (each of Phase 4/5/6 includes this task).
- **Kernel ABI versioning**: elementwise/comparison use the `_v2` stride-aware symbols; per L4-3, `_v1` is retained within v0.2.
- **GPU-less development**: reuse the `MUSAPY_MOCK_MUSA` mock mode; every new kernel needs a mock stub in `kernels.rs` so `cargo test` and CPU pytest run in hardware-less environments.

## 4. Implementation Phases

v0.2-alpha is split into 7 phases. Phase 1 is the foundation (all later elementwise/comparison depend on it).
Phase 2-3 depend on Phase 1. Phase 4/5/6 are mutually independent and can run in parallel. Phase 7 integrates and validates.

| Phase | Effort | Depends on | Parallelizable? |
|---|---|---|---|
| 1. Stride-aware ABI + broadcast | 1.5-2 weeks | v0.1 | — |
| 2. Elementwise + type promotion | 1.5-2 weeks | Phase 1 | — |
| 3. Comparison | 3-4 days | Phase 1 | yes (with Phase 2) |
| 4. Reduction | 1.5-2 weeks | Phase 1 | yes (with 5/6) |
| 5. Init / creation | 1-1.5 weeks | v0.1 (weak dep on Phase 1) | yes (with 4/6) |
| 6. Indexing | 1.5-2 weeks | Phase 1 (views need stride-aware) | yes (with 4/5) |
| 7. Validation & docs | 3-4 days | Phase 2-6 | — |

**Total**: 7-9 weeks (parallelizing Phase 4/5/6 can compress to 6-7 weeks).

## Phase 1: Stride-Aware Kernel ABI + Broadcast Foundation

**Goal**: elementwise kernels support N-dimensional strides; broadcast works; `add` migrates to the new ABI. This is the v0.2 foundation (002-D2).

### Tasks

| Task ID | Task | Deliverable | Basis |
|---|---|---|---|
| P1.1 | Add N-dim indexing helpers to `common.h` | `offset_nd(linear_idx, shape, strides, ndim)`; keep `grid_size_1d` | 002-D2 |
| P1.2 | Upgrade elementwise kernel ABI to `_v2` (stride-aware) | `elementwise.mu`: `musapy_add_f32_v2(a,b,c,ndim,shape,a_strides,b_strides,stream)` | 002-D2, L4-3 |
| P1.3 | Broadcast shape computation (NumPy rules) | `broadcast.rs::broadcast_shape(&[&[usize]]) -> Result<Shape>` | 002-D2 |
| P1.4 | Broadcast stride derivation (incl. composition with input's own strides) | `broadcast.rs::broadcast_strides(layout, target_shape) -> Vec<isize>` | 002-D2 |
| P1.5 | `Layout` extension `broadcast_to(shape)` | `musapy-core/layout.rs` pure fn | 002-D2 |
| P1.6 | Extract common elementwise skeleton from `op_builder.rs` | generalize 3-phase (parse/launch/post) to binary/unary | L1-12, L2-4 |
| P1.7 | Migrate `add` to `_v2` ABI (incl. broadcast) | `elementwise.rs::add` supports different-shaped inputs | 002-D2 |
| P1.8 | Update `kernels.rs` extern decls + mock stubs (`_v2`) | real + mock paths, same signature | L2-2 |
| P1.9 | 0-dim scalar broadcast support | `shape=[]` operand → all strides 0 | L1-11 |
| P1.10 | Broadcast unit + Python tests | `test_elementwise.py::TestBroadcast` | — |

### Interface signatures

```rust
// broadcast.rs
pub fn broadcast_shape(shapes: &[&[usize]]) -> Result<Shape>;          // NumPy rules; incompatible → ShapeError
pub fn broadcast_strides(layout: &Layout, target: &Shape) -> Vec<isize>; // in elements; broadcast dims are 0

// elementwise kernel ABI (C, elementwise.mu)
// void musapy_add_f32_v2(const float* a, const float* b, float* c,
//                        int ndim, const size_t* shape,
//                        const ssize_t* a_strides, const ssize_t* b_strides,
//                        musaStream_t stream);
```

### Acceptance

```python
import musapy as ms
ms.set_default_device("musa:0")
a = ms.array([[1.0], [2.0], [3.0]])   # (3,1)
b = ms.array([10.0, 20.0, 30.0, 40.0])# (4,)
c = ms.add(a, b)                       # (3,4)
assert c.shape == (3, 4)
print(c.tolist())                      # [[11,21,31,41],[12,22,32,42],[13,23,33,43]]
```

## 14. Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Stride-aware kernel ABI rework causes perf regression (contiguous 1D goes through N-dim path) | medium | medium | ✅ mitigated: Phase A contiguous fast path + Phase B parallel reduction + Phase C-lite CPU overhead optimization (-39% latency) |
| Broadcast stride composed incorrectly with input's own strides (non-contiguous input) | medium | high | Phase 1 dedicated tests for transpose-view then broadcast |
| Type-promotion "pre-cast" extra pass perf cost | medium | low | document; acceptable for small arrays; fusion deferred to v3 |
| Reduction block-reduce kernel correctness on large axis | medium | high | shape/axis matrix tests; cross-check against NumPy |
| Integer accumulation overflow tests missed | low | medium | P7.3 dedicated overflow cases |
| Users misuse shared-buffer views (writing a view affects the original) | medium | low | getting-started explains view semantics clearly |
| `__eq__` dunder breaks Array hashability | low | medium | explicit `__hash__=None`; document `ms.equal`-style usage |
| New `.mu` not registered in build.rs → link error | medium | low | each Phase includes build.rs task + clean build verification |
| Developer has no MUSA hardware | high | high | mock mode + CPU fallback; colleague hardware validation (Phase 7) |

## Appendix A: Standard Checklist for Adding an Op (reuse v0.1, updated for v0.2)

Using a new elementwise op `sub` as an example:

1. `kernels/elementwise.mu`: `musapy_sub_kernel<T>` template + `extern "C"` wrappers `musapy_sub_f32_v2`/`musapy_sub_f64_v2` (stride-aware, `<<<grid_size_1d(total), 256, 0, stream>>>`)
2. `rust/musapy-ops/src/kernels.rs`: extern decl (real) + mock stub, same signature
3. `rust/musapy-ops/src/elementwise.rs`: `pub fn sub(...)` reusing the 3-phase skeleton + `cpu_sub`
4. `rust/musapy-ops/src/lib.rs`: `pub use elementwise::sub;`
5. `rust/musapy-python/src/ops.rs`: `#[pyfunction] pub fn sub(...)` (with debug-frame block)
6. `rust/musapy-python/src/lib.rs`: `m.add_function(wrap_pyfunction!(ops::sub, m)?)?;`
7. `rust/musapy-python/src/array.rs`: `__sub__` dunder (if applicable)
8. `python/musapy/__init__.py`: add to import block + `__all__`
9. `python/musapy/_core.pyi`: `def sub(...)` stub (+ dunder stub)
10. `tests/python/test_elementwise.py`: CPU + MUSA-gated tests
11. If a new `.mu` file is needed (reduction/init/indexing): first edit `rust/musapy-ops/build.rs` to compile & archive
